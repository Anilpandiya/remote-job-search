# Apply playbook — weekly operating system

How Anil runs the remote Senior FE (+ agentic-adjacent) pipeline each week. Pair with [`job-tracker.md`](./job-tracker.md) and copy [`weekly-apply-checklist.md`](./weekly-apply-checklist.md) every Monday.

**Default mix:** ~70% Senior Frontend (React/TypeScript) remote · ~30% FE-on-AI / agent platforms (Cursor-like, AI SaaS, agent infra with heavy UI).

**Volume:** 8–12 tailored applications per week — not spray-and-pray.

---

## Weekly cadence

### Monday — target list (15–25 roles)

1. Refresh saved searches and boards (see Sources).
2. Add 15–25 candidates to the tracker with status `researching`.
3. Score each on: stack (React/TS), seniority (Senior / Staff-ish FE), remote policy, agentic overlap.
4. Promote clear fits to `ready-to-apply`; assign Variant A or B.
5. Cap the week’s apply queue at roles you can actually tailor (aim for 8–12 submissions Tue–Thu).

### Tuesday–Thursday — submit 8–12 tailored apps

Each application gets:

- Correct resume variant (A or B).
- Tailored summary + 2–3 JD-matched bullets (see checklist below).
- Tracker row updated to `applied` with date, source, and a concrete next action (e.g. “follow up Fri if no ack”).

Prefer quality over hitting 12. Eight strong apps beat twelve generic ones.

### Friday — pipeline hygiene

1. Follow up on apps that are stale (no ack / no screen after a reasonable window).
2. Move dead ends to `rejected` or `archived`; clear next actions.
3. Note weak spots from JDs or recruiter feedback → feed interview prep + agent learning tracks.
4. Sketch next Monday’s search themes (companies, titles, keywords).

---

## Tailoring checklist (every app)

Do this before clicking Submit — keeps volume honest.

1. **Summary (3–5 lines)** — Role-specific framing: Senior FE platform story (Variant A) or FE + agentic product surfaces (Variant B). Mirror the company’s product language without keyword stuffing.
2. **2–3 JD-matched bullets** — Pull the strongest asks from the JD (e.g. design system, MFE, performance, streaming UX, tool-calling UI) and rewrite existing bullets so those outcomes show first. Keep metrics where you have them.
3. **Stack line** — Confirm React/TypeScript and any must-have tools appear where the ATS/human will see them.
4. **Variant file** — Attach the right PDF; don’t mix A/B for the same company unless they explicitly have two tracks.
5. **Tracker** — Log company, role, variant, source, date, status, next action, notes.

Skip Easy Apply only if you can still complete the same tailoring bar (summary + matched bullets). If the form blocks customization, prefer the career-page apply or a referral.

## Sources

| Source | Use for |
| --- | --- |
| **LinkedIn** | Easy Apply + saved searches (Senior Frontend, React, remote); recruiter inbound; occasional referrals |
| **Wellfound** | Startup / growth-stage FE and AI-product FE roles |
| **Company career pages** | FinTech (Preqin-adjacent) + AI product companies; often fresher than aggregators |
| **Remote-friendly boards** | Remote-only filters when LinkedIn noise is high (e.g. We Work Remotely, Remote OK, similar) |
| **Referrals** | Prefer when available — still tailor; note referrer in tracker notes |

Keep 2–3 saved LinkedIn searches and revisit career pages for a short watchlist of target companies every Monday.

## When to use Variant A vs Variant B

| Variant | Use when | Gate |
| --- | --- | --- |
| **A — Senior Frontend (primary)** | Classic Senior / Staff FE roles: product UI, design systems, MFE, FinTech/SaaS platforms, delivery ownership. Agentic work stays demoted or omitted. | Start as soon as Variant A is “good enough.” Default for the ~70% Senior FE mix. |
| **B — Frontend + Agentic** | AI-product FE, agent platforms, Cursor-like tools, roles that ask for LLM/agent UX, tool-calling UIs, or AI SaaS frontends. Keep FE core; elevate Anthropic/RLGym POC and agentic workflow language. | Unlock only once the **agentic project README** exists so the narrative is demo-backed, not aspirational. Then fill the ~30% AI/agent slice. |

**Rule of thumb:** If the JD never mentions AI/agents/LLM and is a straight Senior FE seat → **A**. If the product *is* the agent/AI surface or the JD calls out agentic UX → **B** (after the demo README). When unsure, score on Monday; don’t force B early.

Applications start with Variant A. Expand to Variant B roles only after that gate — keeps the 30% pipeline honest.
